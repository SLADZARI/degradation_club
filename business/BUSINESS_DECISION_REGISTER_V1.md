# DEMENTOR CLUB — BUSINESS DECISION REGISTER v1

Status: **WORKING DECISION REGISTER / VALIDATION CONTROL**  
Updated: **2026-09-15**

## Purpose

Convert the Business Analysis Pack into an explicit decision system.

Every material business question is classified as one of:

- **DECIDED** — enough authority/evidence exists for the current scope;
- **HYPOTHESIS** — deliberate testable assumption;
- **NEED DATA** — no responsible decision yet; evidence collection required;
- **BLOCKED** — action cannot proceed until a material dependency is resolved.

This register does not redefine Product & Marketing Package `01–15`.

# 1. BA-01 · Market / ICP / Scope

## DECIDED

- ICP should not be invented as demographic persona before evidence.
- market selection should use behavior / situation / value fit first.
- payer and user may differ by value object.
- `Russian-speaking` is a language/cultural reach hypothesis, not a legal/payment geography.
- first validation should use existing Things before building market-specific product variants.

## HYPOTHESIS

### H1 — Primary validation segments

Use first:

- **S1 · Cultural / intellectual audience**;
- **S2 · Creative / knowledge worker**.

Reason:

- strongest fit with current digital Things;
- low fulfillment friction;
- best environment to prove `experience → continuation → return`.

### H2 — Secondary commercial lane

- **S3 · Founder / manager / consultant / team lead** through one narrow Situation / Intervention hypothesis.

Do not reposition the whole product as consulting.

### H3 — Geographic/language scope

Initial research may include transnational Russian-speaking users, but no market geography is approved yet for commerce.

## NEED DATA

- which segment completes Things at higher quality;
- which segment naturally opens another Thing;
- which segment returns;
- source/channel reachability;
- actual value language used by users;
- geography/city/language clusters;
- payer/user split by future offer;
- whether S1 and S2 are truly distinct in behavior.

## BLOCKED

- TAM/SAM/SOM approval;
- commercial geography approval;
- market-specific paid acquisition.

### Exit condition

At least one segment becomes **WORKING MARKET SEGMENT** after repeated external evidence across independent people.

# 2. BA-02 · Business validation / PMF gates

## DECIDED

Evidence ladder is authoritative for business validation:

```text
ATTENTION
→ QUALIFIED EXPERIENCE
→ CONTINUATION
→ RETURN
→ EXPLICIT INTENT
→ COMMITMENT
→ PAYMENT
→ FULFILLMENT / USAGE
→ REPEAT PURCHASE
→ RECURRING NEED
→ SCALABLE ECONOMICS
```

Do not skip levels by interpretation.

PMF is not currently claimed.

## HYPOTHESIS

Current Program v0 should be sufficient to test the first four levels if Phase 1 implementation produces clean external traffic and semantic instrumentation.

## NEED DATA

- external qualified entry;
- Form-aware experience;
- Thing→Thing continuation;
- expected-window return;
- segment-level comparison;
- explicit next-value language.

## BLOCKED

- willingness-to-pay conclusions before a concrete offer;
- repeat/recurring conclusions before successful fulfillment;
- scalable economics before repeat behavior.

### Exit condition

At minimum Gate D (`Proof of Return`) must have a credible signal before designing recurring value.

# 3. BA-03 · GTM / Demand validation

## DECIDED

Use now:

- personal/private share;
- owned Telegram as Programming / re-entry channel;
- narrow social/editorial fragments;
- relevant partner/community distribution;
- search where exact object already exists.

Do not use:

- Board as generic acquisition surface;
- Home as default exact campaign landing;
- paid media as scale channel yet.

Every campaign/test must land on an exact Thing / Entry Object.

## HYPOTHESIS

### H4 — Lane A

S1 can be reached efficiently through share + editorial/social distribution around concrete Things.

### H5 — Lane B

S2 responds better to utility/situation framing around Course/Tool/Method than generic brand framing.

### H6 — Lane C

One narrow Situation class can generate qualified Intervention interest through referrals/authored work.

## NEED DATA

- acquisition effort by channel;
- qualified experience per source;
- message fit by segment;
- continuation by source/channel;
- warm-network bias vs external audience;
- return by source/channel.

## BLOCKED

Paid acquisition scale until:

- exact offer exists;
- experience works externally;
- fulfillment works;
- payment/legal path is valid;
- attribution reaches payment + usage.

# 4. BA-04 · Commercial offer / pricing

## DECIDED

Not current business model facts:

- universal paid Membership;
- default subscription;
- premium status tiers;
- broad paid catalog;
- checkout-first strategy.

Payment must attach to a concrete value object.

## HYPOTHESIS

Offer classes eligible for later test:

### O1 — paid digital Thing / Tool

Research corridor: `€8–15` or local equivalent.

### O2 — live online experience

Research corridor: `€25–50`.

### O3 — bounded small offline experience

Research corridor: `€90–190`, subject to cost base.

### O4 — high-touch Intervention

Price only after one Situation is validated.

### O5 — physical Thing

Only after payment + fulfillment readiness.

These are research hypotheses, not public approved prices.

## NEED DATA

- which value object produces explicit paid intent;
- real price acceptance;
- payment conversion;
- fulfillment usage;
- refund/failure;
- repeat interest/purchase.

## BLOCKED

Any paid test before:

- seller/legal entity;
- payment geography/provider;
- tax/invoice approach;
- refund/cancellation rule;
- fulfillment owner;
- commerce readiness.

Recurring offer additionally blocked until repeat purchase + recurring need appear.

# 5. BA-05 · Finance / unit economics / capacity economics

## DECIDED

Cost buckets remain separate:

- acquisition;
- production/editorial;
- fulfillment;
- payment;
- fixed platform/team.

Revenue is not viability by itself.

Official LTV is prohibited before repeat behavior.

## HYPOTHESIS

None of the scenario values from market research should be treated as forecast.

They may remain sensitivity examples only.

## NEED DATA

For each selected Thing / future offer:

- production/editorial hours;
- maintenance time;
- fulfillment hours/cost;
- fixed delivery cost;
- payment fees;
- refund/failure allowance;
- realistic capacity;
- founder/key-person labor;
- current monthly fixed cost;
- cash requirement.

For first paid offer additionally:

- AOV;
- contribution per transaction;
- break-even volume;
- time to repeat.

## BLOCKED

- official CAC/LTV ratio;
- payback target;
- recurring P&L;
- 12-month business forecast presented as forecast.

These remain blocked until real paid cohorts exist.

# 7. BA-07 · Legal / compliance / commerce readiness

## DECIDED

Commerce readiness is not a feature flag.

```text
SELLER / LEGAL ENTITY
CUSTOMER/PAYMENT GEOGRAPHY
PRODUCT TYPE
PRICE / CURRENCY
PAYMENT PROVIDER
TAX / INVOICING APPROACH
REFUND / CANCELLATION
FULFILLMENT OWNER
DATA / PROCESSORS
PUBLIC TERMS / PRIVACY
```

## HYPOTHESIS

None. Legal/commercial facts should not be guessed.

## NEED DATA / OWNER DECISION

- selling legal entity;
- first commercial geography;
- payment provider;
- tax/invoicing mechanism;
- supported currencies;
- customer support identity/process;
- final data processor map;
- IP/contributor terms if user material is involved.

## BLOCKED

Until resolved:

- public checkout;
- actionable preorder;
- paid media to commercial offer;
- recurring billing;
- cross-border commerce scaling.
