# DEMENTOR CLUB — GTM & DEMAND VALIDATION PLAN v1

Status: **DRAFT / BUSINESS VALIDATION PLAN**  
Updated: **2026-09-15**

## Purpose

Convert Distribution semantics into a concrete demand-validation operating plan.

This document does not redefine channels or positioning.
It selects what to test, with whom, through which route, and what evidence determines the next decision.

---

# 1. GTM principle

> **DISTRIBUTE THE THING. VALIDATE THE DEMAND. DO NOT ADVERTISE THE ORGANIZATION FIRST.**

GTM unit:

```text
SEGMENT HYPOTHESIS
→ SPECIFIC THING / OFFER
→ CHANNEL
→ MESSAGE
→ EXACT ENTRY OBJECT
→ EXPERIENCE
→ EVIDENCE
→ DECISION
```

---

# 2. Initial validation lanes

## Lane A — Cultural / intellectual audience

### Goal

Validate attention → experience → continuation.

### Candidate objects

Use current safe Program Things / digital experiences.

### Channels

- private share;
- Telegram owned / adjacent communities;
- short social/editorial fragments;
- partner/editorial mentions.

### Success evidence

- qualified experience;
- Thing→Thing;
- private share;
- expected-window return.

### Do not optimize yet

- follower count;
- Home traffic;
- membership applications.

---

## Lane B — Creative / knowledge worker

### Goal

Validate utility + repeat use / paid adjacency.

### Candidate objects

- Course;
- Tool / Method;
- recurring Practice where actual participation exists.

### Channels

- professional communities;
- founder/creative circles;
- relevant newsletters / Telegram;
- direct referrals.

### Evidence

- completion/use;
- Situation language;
- request for continuation;
- explicit interest in concrete live/paid format.

---

## Lane C — Situation / Intervention

### Goal

Validate high-value concrete need without turning Dementor into generic consulting.

### Offer shape

One narrow Situation class.

### Acquisition

- referral;
- authored work;
- partner/community context;
- direct qualified outreach only where the Situation is plausible.

### Evidence

- qualified request;
- willingness to commit;
- paid test if approved;
- outcome/referral/repeat.

# 3. 8-week validation cycle

## Weeks 1–2 — Baseline / instrument

- isolate external population;
- select 3 reference Things;
- ensure exact entry routes;
- define experience-start signal;
- prepare 3–5 message variants tied to actual Things;
- no paid scale.

## Weeks 3–4 — Organic demand

Run:

- personal share;
- Telegram/editorial posts;
- small partner/community distribution;
- direct invited cohort where appropriate.

Collect:

- qualified entry;
- experience;
- continuation;
- qualitative response.

## Weeks 5–6 — Segment comparison

Compare S1 / S2 and, if feasible, narrow S3.

Do not compare only CTR.

Compare:

- experience quality;
- continuation;
- return;
- explicit next-value language;
- acquisition effort.

## Weeks 7–8 — Commercial-intent probe

Only on the segment/object combination showing value:

- interest CTA;
- waitlist/reservation request;
- concrete offer language;
- payment test only if commerce/legal readiness exists.

End with PASS / ITERATE / HOLD / FAIL / INVALID.

# 4. Channel roles

| Channel | Role | Use now? | Primary evidence |
|---|---|---:|---|
| Personal share | trust-led discovery | YES | recipient experience + continuation |
| Telegram owned | programming / re-entry | YES | experience / return |
| Social short-form | discovery | YES, narrow | qualified entry, not views |
| Search | situation / precise object | YES where indexed | experience + continuation |
| Partner community | contextual borrowed trust | YES, small | downstream quality |
| Event / QR | physical continuation | when real | scan→experience |
| Paid acquisition | scale test | NOT YET | only after paid/value proof |
| Board | current activity intent | NO as generic acquisition | contextual internal discovery |
| Home | direct/current-program intent | NO as default campaign landing | program exploration |

# 5. Message testing

Message variables may include:

- observation / hook;
- premise;
- proof format;
- literal CTA.

Must not vary truth.

Test:

```text
OBSERVATION-FIRST
vs
UTILITY-FIRST
vs
THING-FIRST DEMO
```

by segment.

Do not test:

- fake urgency;
- unapproved scarcity;
- invented outcomes;
- club-status language as a substitute for value.

---

# 6. Cohort discipline

Every GTM test records:

- segment hypothesis;
- source/channel;
- message variant;
- entry object;
- experience definition;
- next step;
- cost/effort estimate;
- sample validity.

Separate:

- founder friends / warm network;
- existing community;
- partner audience;
- cold external.

Do not combine them into one “conversion rate”.

---

# 7. Demand evidence ladder

```text
OPEN
< QUALIFIED EXPERIENCE
< CONTINUATION
< RETURN
< EXPLICIT INTEREST
< COMMITMENT
< PAYMENT
< REPEAT
```

Each GTM report must say which level was observed.

---

# 8. Initial decision matrix

### Strong experience, weak acquisition

Improve distribution/message/channel fit.

### Strong acquisition, weak experience

Do not scale. Fix Thing/promise fit.

### Strong experience + continuation, weak return

Improve Program memory / real continuation cadence.

### Strong return, weak paid intent

Keep value free / test different paid object. Do not force subscription.

### Paid intent, weak fulfillment

Stop selling until delivery is reliable.

---

# 9. Paid media gate

Paid acquisition may begin only when:

- a concrete offer exists;
- destination is exact;
- external experience is proven;
- fulfillment is ready;
- payment/legal path is valid;
- attribution can distinguish spend → payment → usage.

Start with controlled cells, not brand traffic.
