# DC-9 Result + Routing Hypotheses

Status: **DRAFT PRODUCT HYPOTHESES / NOT CANON**  
Date: 2026-08-31

## Boundary

The approved DC-9 result system currently requires nine independent sphere results and explicitly forbids a universal Dementor score, aggregate psychological score, general psychotype or automatic membership permission from a sphere result.

This file therefore stores result-language and routing ideas separately from approved production semantics.

Nothing here may be implemented until the relevant Club content/entities and routing rule are explicitly approved in `dementor-club`.

## Result direction: technical conclusion, not personality type

Avoid:

- `Ты рационал`;
- `Ты осознанный`;
- `Ты правильный Дементор`;
- universal "your type" framing.

Prefer technical/systemic language that classifies behavior without pretending to diagnose the whole person.

Editorial examples only:

### СИСТЕМА ИЗБЕГАНИЯ ЛИШНЕЙ СЛОЖНОСТИ

`Состояние: стабильное.`

### РАЦИОНАЛЬНАЯ НАГРУЗКА

`4.3 / 5 — превышение нормы.`

### СОПРОТИВЛЯЕМОСТЬ ФАКТАМ

`1.8 / 5 — недостаточная.`

### СПОСОБНОСТЬ ПЕРЕДАВАТЬ ОТВЕТСТВЕННОСТЬ

`3.9 / 5 — развита.`

### РИСК САМОСТОЯТЕЛЬНОГО ВЫВОДА

`Высокий.`

These examples are tone/prototype material only. They are not approved axes and must not accidentally create a tenth diagnostic system.

## Satirical payoff rule

Humor should accumulate through the experience:

1. question nearly serious;
2. answers believable;
3. occasional system transition;
4. result provides the strongest absurd administrative classification.

The result should make the user recognize that a normal strategy has been processed by an overly formal Club apparatus.

## Routing hypothesis

Potential future product behavior:

`SPHERE RESULT → RELEVANT APPROVED CLUB MATERIAL`

Possible destination classes only after they actually exist and are approved:

- article;
- project;
- card/artifact;
- event;
- course/product;
- community format;
- named sphere-related Club material.

Example editorial framing:

> У вас обнаружено повышенное содержание контроля. Начните деградацию здесь.

This is **not yet an approved routing rule**.

## Hard restrictions

Do not:

- invent a sphere course that does not exist;
- invent a “Dementor of the sphere” role;
- invent membership mechanics;
- skip the approved identity/membership/community transition;
- use one sphere result as permission or rejection for membership;
- create an aggregate psychotype to choose content;
- route to unpublished/internal ideas as if they were public Club products.

## Candidate routing logic for future evaluation

If approved later, content routing should probably use one or more factual sphere values rather than a new total score.

Candidate families:

- strongest sphere signal → one relevant approved item;
- weakest / most conflicted sphere → one contrasting item;
- user-selected sphere → direct continuation;
- completed 9/9 map → 1–3 editorial recommendations, presentation only.

Any rule must be deterministic enough for QA and explainable internally, while the public copy remains simple.

## Product test question

The quiz should answer not only:

> What did the user score?

but eventually:

> What useful, real thing in Dementor Club should this person see next?

Until the Club has sufficient approved destination content, the correct product answer may simply be the existing approved Community transition rather than invented personalization.
