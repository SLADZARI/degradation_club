# Design-system audit — 2026-08-26

Scope: official site implementation branch `agent/dementor-ui-lab-v4` plus approved design/component/asset documentation and the independent `logic-awareness` project boundary.

## Executive summary

The project already has a substantial design system, but it is distributed across documentation and implementation layers. The main problem is not absence of rules; it is lack of normalization and ownership.

### What is already mature

- core palette;
- acid contrast contract;
- 12/8/4 grid direction;
- editorial typography roles;
- large-scale rhythm tokens;
- DIA motion tokens;
- Dementor Ink density/integration system;
- raster production contract;
- component/page-family rules;
- explicit project-local identity boundary.

### What is incomplete

- machine-readable unified token registry;
- final font families;
- semantic aliases between primitive values and components;
- project token registries;
- consistent normalization of old raw values;
- explicit ownership of one-off authored exceptions.

## Findings

### F01 — colour core is stable

Canonical:

- PAPER `#F2F0E8`
- INK `#111111`
- ACID `#D8FF3E`

Decision: promote to primitive tokens.

### F02 — acid contrast is stronger than component CSS

Accessibility layer explicitly prevents light text on ACID.

Decision: `text.onSignal = ink` is an invariant and cannot be project-overridden.

### F03 — line alpha drift

Found both:

- `rgba(17,17,17,.18)` in older styles;
- `rgba(17,17,17,.20)` in current `--dc-line`.

Decision: `.20` is normalized candidate. Migrate `.18` opportunistically rather than creating two line tokens without semantic distinction.

### F04 — muted `#777` is legacy

The old `--muted:#777` is not supported by a clear semantic contract in the newer layers.

Decision: do not preserve as canonical primitive yet. Prefer semantic secondary text/opacity after contrast review.

### F05 — shell max-width drift

Found 1500px in legacy style while docs/components target 1440–1600 / 1600.

Decision: normalize `layout.shell.max = 1600px`; treat 1500px as legacy implementation value until visual regression check.

### F06 — rhythm system is already tokenized

`tight / medium / wide / huge` are coherent, responsive and used by page families.

Decision: canonical foundation tokens. Do not collapse into generic 8-point spacing.

### F07 — mobile rhythm is intentionally different

Mobile values are explicit overrides at 700/430/390/360.

Decision: preserve. Mobile is separate composition, not scaled desktop.

### F08 — typography role system exists, font identity is unfinished

Current:

- Reading: Inter fallback;
- Display: Arial Narrow/Helvetica Neue fallback.

Approved guide says both are directions/fallbacks, not final identity.

Decision: tokenize roles, not temporary family names as brand canon.

### F09 — display → reading substitution on mobile is intentional

Current CSS switches display elements to reading font on mobile to protect legibility/Cyrillic.

Decision: document as responsive typography policy.

### F10 — body/lead measures are valid tokens

`66ch` body and `29ch` lead are repeated system values.

Decision: promote to typography measure tokens.

### F11 — local text measures are composition exceptions

Values such as 52ch, 31ch, 23ch and quote-specific 12/13ch serve authored layouts.

Decision: do not create dozens of global measure tokens.

### F12 — DIA motion has a clean primitive set

Canonical candidates:

- ease `.2,.8,.2,1`;
- 220ms;
- 480ms;
- 820ms.

Decision: promote.

### F13 — duplicate motion values exist outside DIA

`ui-v2.css` contains older hard-coded durations/easings alongside DIA tokens.

Decision: migrate reusable component motion to DIA aliases; preserve authored long Ink transitions as scene-level exceptions.

### F14 — focus offset drift

Found focus outline offsets 3px and 4px depending layer.

Decision: keep both temporarily only by semantic control family or normalize after visual/accessibility QA. Do not add more values.

### F15 — disabled opacity drift

Found `.4` and `.42`.

Decision: normalize proposal `state.disabled.opacity = .42` after checking legacy visuals.

### F16 — Dementor Ink density is a real system

L0/L1/L2/L3 has both target distribution and implementation behaviour.

Decision: canonical illustration semantic layer.

### F17 — Ink integration has reusable primitives

Repeated:

- edge clamp;
- density tilts;
- multiply blend;
- ~1.05 contrast;
- 1px ink border;
- acid label with ink foreground.

Decision: promote to illustration integration tokens.

### F18 — authored Ink scene values must remain local

Examples:

- specific negative margin;
- object-position;
- label copy;
- exact line placement;
- scene rotation beyond density primitive.

Decision: keep in page/scene CSS.

### F19 — artwork and integration must remain separate

Approved production docs explicitly forbid CSS grunge/vector substitutes for actual raster art.

Decision: no token system may be used to procedurally fake Dementor Ink.

### F20 — project identities need namespaces

Logic & Awareness already has explicit permission for Ministry/Soviet subsystem and muted bureaucratic red.

Decision: create project token namespace, keep red value TBD until approved/extracted from canonical project assets.

### F21 — Soviet visual language is not global Club identity

Decision: hard boundary. Project-only unless separately promoted.

### F22 — final font selection is the largest unresolved foundation decision

Decision: do not pretend current fallback stacks are finished. Next typography milestone should compare Cyrillic-capable candidates and migrate via role aliases.

## Normalized token groups

### Canonical now

- core colours;
- acid foreground contrast;
- grid column counts;
- Mouthwash rhythm;
- DIA durations/ease;
- Ink density;
- Ink edge/tilt primitives;
- raster-only illustration delivery rule;
- typography roles/measures.

### Candidate / needs migration

- line alpha `.20`;
- shell max 1600px;
- disabled opacity `.42`;
- focus offset normalization;
- semantic secondary text token.

### Explicitly unresolved

- final reading font;
- final display font;
- exact project warning red;
- full per-project registries.

## Recommended implementation sequence

1. Keep documentation branch as reviewable source-of-truth proposal.
2. Review semantic names and unresolved candidates.
3. Merge docs without immediately rewriting every CSS file.
4. Add a token compatibility layer mapping new semantic names to current variables.
5. Migrate components family-by-family.
6. Add project registries only when repeated approved rules exist.
7. Select final typography separately and perform a dedicated migration.

## Anti-goal

Do not turn the design system into a catalogue of every number found in CSS. The goal is fewer meaningful decisions with explicit ownership, not more variables.
