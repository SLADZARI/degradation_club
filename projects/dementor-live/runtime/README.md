# Dementor Live — локальный первый slice

**Для продолжения работы начни с [START_HERE.md](START_HERE.md).** Там подготовлены команды среды, вход для нового чата и карта источников. Текущий доказанный статус — [CURRENT_STATE.md](CURRENT_STATE.md); HANDOFF описывает предыдущий срез передачи.

Отдельный браузерный прототип. Не использует код Battle, Robo или клубного сайта, внешние сервисы и платную инфраструктуру. Установка пакетов для обычного запуска не нужна. Требуется Node.js 22 или новее.

## Запуск

Открой терминал в этой папке и выполни:

```sh
npm start
```

Открой **http://127.0.0.1:4173**. Введи имя жителя. Для второго настоящего игрока открой этот же адрес в другой независимой вкладке либо нажми `?` → «Открыть вход второго игрока». Каждый вход получает отдельный кошелёк и инвентарь; сервер держит общий мир. Нельзя просто открыть `index.html` без сервера.

Перезагрузка вкладки сохраняет её жителя через `sessionStorage` с идентификатором; игровой мир хранится сервером в `data/world.json`. Новая независимая вкладка — новый житель. Это локальная идентичность без аккаунтов, не готовая система авторизации публичной игры. Закрытие вкладки прекращает голод и незавершённые действия. Сервер слушает только loopback, подключения с другого компьютера не настроены.

## Управление

- WASD или стрелки — движение, Shift — бег с расходом сил.
- Нажатие на свободную землю — идти по найденному пути. Нажатие на объект — подойти к нему; E выполняет действие.
- E — взаимодействие рядом; удержание повторяет добычу или работы.
- 1 — топор, 2 — кирка, F — съесть порцию еды.
- Enter — локальный чат, Escape — отмена пути и действия.
- Колесо мыши и кнопки `− / ◎ / +` — масштаб и центрирование.

Возьми инструменты в мэрии → добывай древесину и камень → неси на приёмку площади → получай игровую оплату → выполняй строительные этапы → купи свободный участок. Оба игрока видят друг друга и общее продвижение, но получают деньги только за собственный принятый вклад. Этапные материалы действительно расходуются.

Инструменты изнашиваются, замена в мэрии бесплатна. Еда собирается с возобновляемых кустов. Дух не работает: он может подойти к кусту и восстановиться, даже если рюкзак полон. Сосед с порцией еды может подойти и угостить его. В прототипе голод возвращает духа к палатке; переносимые вещи сохраняются. Это явные правила тестового slice, не обновление замороженного GDD.

## Что реализовано и что проверено

Исходники содержат авторитетный Node.js сервер, HTTP-команды и SSE-синхронизацию клиентов, сохранение JSON, отдельные инвентари, ограничение груза, инструменты, конечные запасы древесины/камня, общий проект из трёх этапов, оплату, участки, голод/духа/еду, бег и чат. Интерфейс реализован заново: карта и компактные плавающие панели; статичная картинка не используется вместо мира.

**Реально выполнено:** синтаксические проверки JavaScript; 16/16 тестов игровой модели (`npm test`). Проверены одиночное завершение площади и расход материалов, оплата без дублирования, конкуренция двух записей игроков за ресурс/участок/последнюю работу, переноска, инструменты, столкновение с рекой, голод только онлайн, самовосстановление и помощь едой, восстановление модели из сохранённого JSON, приватность снимков состояния и локальный чат.

**Минимальная версия проверена в исполнении:** 11 сетевых сценариев HTTP/SSE и 13 групп браузерных проверок в двух независимых Chrome-контекстах. Через интерфейс пройдены инструменты → добыча → груз → сдача → оплата → все стадии площади → покупка двух участков. Проверены совместная последняя работа, чат, дух/еда/помощь, отсутствие офлайн-голода, река, reload и реальный рестарт процесса. Консоль и сеть: 0 ошибок. Обычная основная цепочка выполнялась через UI; только сфокусированные голод/гонки используют изолированные фикстуры. Сервер на исходном компьютере оставлен работающим на `127.0.0.1:4173`. Подробности и отчёты — CURRENT_STATE.md.

## Тесты и изменяемые параметры

```sh
npm test
npm run test:integration
npm run test:browser
```

Вторая команда запускает отдельный сервер на порту 4178 с временным хранилищем и проверяет HTTP/SSE. Третья использует 4179, установленный Chrome и доступный Playwright (обычная игра не зависит от Playwright). Можно указать путь к модулю через DEMENTOR_PLAYWRIGHT_MODULE. Оба набора выполнены успешно. Для интенсивных сфокусированных случаев используются тестовые фикстуры. Результаты и настоящие скриншоты — reports/ и docs/verification/. npm run check показывает отдельно записанный PASS только при совпадении хеша проверенного runtime.

Все изменяемые числа находятся в `config.mjs`: бюджет, потребность проекта, цены, вес груза, длительность действий, износ, голод и восстановление еды. Они предназначены исключительно для прототипа. Площадь выплачивает 280 PAPER; общего заработка хватает на два участка по 120 при соразмерном вкладе, равный заработок не гарантируется. Единственный источник выплат — городской фонд, покупка участка возвращает деньги городу.

Для ускоренного воспроизведения голода тестовый сервер запускается `node server.mjs --test`; маршрут `/__test` существует только в этом режиме и требует заголовка `x-test-key: local-integration-tests`. Обычный сервер не предоставляет этот маршрут. Не публиковать сервер с тестовым режимом.

## Границы slice

Кузница и мост пока обозначены на карте, река непроходима. Строительство личного дома, производство, авторские здания и голосование, PvE, монетизация, внешние аккаунты и публичный деплой не реализованы. Облик блоковых героев и бумажная палитра воспроизведены простыми рисуемыми формами по трём референсам; изображения не копировались как фон игры. Визуал просмотрен на desktop и мобильном экране 390 px; это механический slice с простой графикой.

[Основной документ согласованной концепции](https://github.com/SLADZARI/degradation_club/blob/docs/dementor-live-global-audit-05/projects/dementor-live/CORE_AND_FIRST_LEVEL_v0.1.md). Тестовые числа прототипа не добавлены в этот документ.

## Два устройства в одной сети

Оба игрока открывают сетевой адрес, который печатает npm start (сейчас http://172.20.10.3:4173), и вводят разные имена. Сервер работает только на одном Mac. WASD/стрелки — идти, Shift — бег, E — действие, 1/2 — инструменты, F — еда.

Первый общий проект — площадь. Затем открывается стройка общественной кузницы внизу справа: 24 древесины, 24 камня и три этапа работ. Материалы сдавать у левого края кузницы, строить — внутри площадки. Каждый получает оплату за свой вклад. Производство в кузнице пока отсутствует. Сохранённый мир продолжается без сброса.

Полная инструкция подключения: START_HERE.md. Проверка сетевого доступа двумя браузерами: npm run test:lan (отдельный временный мир).

## Склад, рюкзак и мэрия

Внизу есть кнопка **Рюкзак**: выложить личные ресурсы на землю (одну единицу или всё). Кучку можно подобрать через E, в том числе другому игроку. Вес переноски соблюдается.

**Городской склад** между нижними участками принимает лишнюю древесину и камень за небольшую плату: пока по 1 PAPER/шт., дешевле прямой сдачи на стройку. У города появляются физические запасы. Вместимость и бюджет конечны и видны при приёмке.

**Доска работ** слева от палатки мэрии: текущие поставки, стройка и курьерские заказы. Курьер берёт заказ на доске, забирает городской груз на складе и физически доставляет к отметке мэрии севернее инструментов. Груз занимает рюкзак, не продаётся как личный; оплата после доставки. Отмена полученного заказа с возвратом — на складе.

Подробности и границы: docs/CITY_WAREHOUSE.md. Проверки нового UI-пути: `npm run test:city`; проверки модели: `npm run check`. Новый склад и заказы добавляются к прежнему сохранению без сброса.

## Камера, изготовление и магазин

Камера всегда следует за героем. ☷ «Места города» рядом с масштабом — выбор цели и обычный путь к ней. Готовая кузница изготавливает топор/кирку из личных 2 дерева и 2 камня: 48 прочности. Магазин вверху карты продаёт инструменты по 180 PAPER, 160 прочности. Бесплатные стартовые имеют 16. Улучшенные не ремонтируются бесплатной выдачей, сохраняют износ при перезагрузке. Числа пробные; текущий инструмент заменяется новым своего вида. Полные границы: docs/TOOLS_AND_CAMERA.md; проверка: npm run test:tools.

## Диагностика рывков камеры

`npm run test:performance` — короткий замер в отдельном мире. Постоянная камера теперь использует общую с героем плавную позицию между сетевыми обновлениями; скрытые панели не пересоздаются на каждом пакете. Причина, ограничения и замеры — docs/PERFORMANCE.md. Для загрузки исправления достаточно обновить страницу игры.

## Мост и другой берег

После кузницы строим мост: 24 дерева, 16 камня, три стадии. Приёмка и рабочая точка — в ☷ «Места города». На доске можно взять доставку городских запасов со склада на мост; выплата только за перевозку. После открытия оба игрока переходят реку и добывают настоящие ресурсы другого берега, затем возвращаются с грузом. До готовности и вне мостовой полосы река непроходима. Полные правила/ограничения: docs/BRIDGE_AND_EXPLORATION.md. Проверка: npm run test:bridge.

## Площадь: идеи памятника и общая музыка

Пьедестал на площади принимает ответ на вопрос о будущем памятнике и платит 50 PAPER от мэрии однократно. Музыкальный автомат запускает общий MP3 за 2 PAPER, принимает пожелания треков за 1 PAPER. Звук включается отдельно у каждого слушателя; поздний слушатель подключается к общей позиции. Два оригинальных демотрека в комплекте, загрузка MP3 с компьютера сервера через UI; аудиофайлы пользователя сохраняются в data/music вне ZIP. `npm run test:plaza`, инструкция docs/PLAZA_OBJECTS.md.
