## Actual proof: three distinct cases, no invented account verification

1. **Both devices and active old session:** existing one-use transfer ticket, 256-bit code, 10-minute expiry, authenticated issuance; redeem `CharacterId + code + 128+ bit client requestId`. First redeem persists a fresh bearer, revokes old bearer/SSE, and saves a salted digest of the code+requestId for 10-minute **idempotent retry**; same proof returns the same bearer after ACK loss and restart, other requestId is rejected.
2. **All browser session bearers lost BUT independent offline recovery key was previously saved:** on deliberate new-player onboarding or authenticated `/enroll`, issue **one 256-bit offline rescue secret**. Its salted/domain-separated SHA-256 verifier resides on the *same existing resident* and never appears in a world snapshot. A different browser redeems `CharacterId + recoveryCode + high-entropy requestId`; a saved 15-minute pending handoff permits the same request to recover the same bearer after HTTP ACK loss or process restart. Different concurrent requestId is rejected; explicit bearer-authenticated `/confirm` rotates the offline rescue key; a lost confirmation response cannot lose the bearer already received. Existing legacy bearer is not required for the claim. New key must be saved privately after confirmation.
3. **Every bearer lost AND no offline secret or previously bound independent proof:** **no self-service recovery is technically possible** under the legacy anonymous trust model. Name, public CharacterId, six-digit phone number, subjective gameplay anecdotes, IP, device fingerprint, screenshot, informal chat, or knowledge of public plots do **not** establish ownership. Never guess one of the four original same-name `90` IDs or reveal saved raw bearer. **Fail closed**: leave resident/ledger untouched; do not issue token, merge or grant PAPER. Owner/Lead must separately approve a *specific evidence-based support adjudication* with authenticated operator, two-person review, time-bounded scope, provenance/audit and appeal/denial policy. The system cannot conjure historic proof that was never enrolled. This historic #90 case remains P0 OPEN.

## HTTPS API contract (all JSON POST + exact Origin, no query)

- `/api/identity/transfer/create` / `revoke`: existing bearer; `create` returns `{characterId, code, expiresAt}` exactly once.
- `/api/identity/transfer/claim`: no bearer; `{characterId,code,requestId}`, where requestId is 32–64 lower-case hex chars generated from crypto RNG in the claiming client. Returns `{id,token,replayed}`. Client MUST save requestId and code until acknowledgement or expiry; same proof retry returns same token; other proof does not.
- `/api/identity/recovery/enroll`: current bearer and `{acknowledgeSecureStorage:true}`. Replaces prior rescue key and invalidates pending handoffs. Returns `{characterId,recoveryCode,createdAt}` **only once**. Do not auto-enroll if user cannot save key.
- `/api/identity/recovery/claim`: no bearer; `{characterId,recoveryCode,requestId}`. Returns `{id,token,confirmationRequired:true,replayed}`; old bearer immediately invalid. Same proof replay remains stable across server restart while pending.
- `/api/identity/recovery/confirm`: **new** bearer, `{acknowledgeStoredToken:true}`. Rotates offline key; returns new `recoveryCode`. After this ACK, previous rescue key cannot recover. If response lost, user still has new bearer and can `/enroll` again.
- When explicitly enabled, `POST /api/join` requires `acceptRecoveryKit:true` and same-origin HTTPS, otherwise returns **428 before creating resident**. Success returns the initial `recoveryCode` once. This is deliberately not backward-compatible when the flag is ON; Dev2 UI must implement **show/save/confirm** before any release.
- Both modes preserve immutable server-side `CharacterId`, original wallets, treasury, plots, material conservation, receipts, requestId history and ledger. Never clone gameplay state.

## Source guardrails and release gates

- **Feature OFF by default.** On non-test servers, BOTH `DEMENTOR_IDENTITY_TRANSFER_ENABLED=1` and `DEMENTOR_IDENTITY_EDGE_ADMISSION=confirmed` plus an HTTPS `DEMENTOR_PUBLIC_URL` are necessary. Operator must attach actual Nginx edge evidence before treating env flag as legitimate. `--test` isolated local loopback only, no public deployment.
- **SSE bearer URL:** source previously accepted `/api/events?token=<bearer>`; when the new feature is ON, URL query is rejected and authenticated SSE requires the **Authorization** header. Other `/api/*` endpoints never accept URL bearer. Dev2 must replace native EventSource with stream-fetch/Authorization or propose another reviewed no-secret-URL transport. Existing clients use the old route while feature is OFF, so there is no false claim that current production logging is already fixed.
- **Rate control:** per-character admission count 5/10min is saved durably with the resident, surviving game restart (single-writer current runtime). A broad emergency process counter is only extra protection, not an IP classifier. Ignore untrusted `X-Forwarded-For`; `req.socket.remoteAddress` is shared by all clients behind Nginx. Actual Nginx `limit_req_zone $binary_remote_addr` (validated trusted client IP provenance) + `limit_req`, burst/error 429, upstream single writer and optional external limits must be independently checked before enabling. See proposed `deploy/identity-edge-example.nginx`, NOT active config.
- **Bearer at rest:** legacy `player.token` is plaintext in the existing save and **NOT** fixed in this G5 candidate. All new transfer and recovery **codes** are only hashed, except the one-time HTTP response and user-held copy. Hashing/rotating legacy bearer at rest and sensitive backup retention require separately reviewed migration.
- **Secrets/logs:** never put transfer key/recovery key/bearer/requestId into URL, server exception, Nginx `$request_uri` access log, client analytics, bug report, screenshot, Git or shared chat. Do not use `/api/admin/treasury` or SSH key as player recovery. No Club account integration.
- **ACK/cold restart:** retry proof persists in world, no grant of PAPER or new resident. Throw-before-save in isolated `--test` fault injection must leave old token and old proof valid; when recovered, one new bearer and zero duplicated transactions. A response lost after *pending handoff expiry* can still use a valid offline rescue key for a new attempt; transfer-only ticket has bounded 10min retry and otherwise needs a separate credential.
- **Operator support for pre-code legacy saves:** require a prior independent possession proof tied to exact CharacterId and an approved Decision for audited, dual-controlled break-glass issuance; otherwise DENY without editing world. For #90 four previous namesakes with wallets `[0,0,151,354]` are **not** ownership evidence. Human claimant mapping remains UNKNOWN, despite SRE's verified historic record retention.
