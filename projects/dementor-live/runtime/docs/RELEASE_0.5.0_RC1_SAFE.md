Новый продуктовый backlog и разграничение уже реализованного vs новых решений: [триаж всей записи](../../qa/PLAYTEST_2026-10-20_RECONCILIATION.md).

## Статус и граница безопасности
Эта ветка готовит выпуск, но не производит VM SSH/деплой автоматически. GitHub Actions доказывает компиляцию и игровые тесты на изолированных мирах, не целостность текущего `dementor-live-world`. Живой backup и снимок `/api/health` должен быть получен оператором с допуском на VM.

**НЕ использовать** `deploy/publish-clean-world.sh --reset-world`, `docker compose down -v`, `docker volume rm`, `docker system prune`, прямое копирование локального `data/world.json` в production. Инструмент ниже **не удаляет** мир.

## Один проверяемый выпуск на VM
На VPS запустить в **отдельном чистом checkout релизной ветки** (не в `/srv/dementor-live/app`):

```bash
git clone --branch release/dementor-live-civic-p3-safe-upgrade-2026-10-20 \
  https://github.com/SLADZARI/degradation_club.git \
  /srv/dementor-live/release-candidate
cd /srv/dementor-live/release-candidate/projects/dementor-live/runtime
git rev-parse HEAD   # убедитесь в точном одобренном SHA
bash deploy/publish-preserve-world.sh --dry-run
```

Не копировать URL/checkout из этого примера, если каталог уже существует: сначала **read-only** осмотреть существующий путь. Для уже существующей staging-копии использовать собственный чистый checkout exact SHA.

После того как GitHub CI и `--dry-run` PASS, а пользователь дал окно переключения:

```bash
# указать фактический ПОЛНЫЙ SHA прошедшего CI коммита
bash deploy/publish-preserve-world.sh --apply <APPROVED_40_CHAR_SHA>
```

## Инварианты скрипта
1. Проверяет реального владельца Compose `dementor-live/game`, наличие **существующего** тома `dementor-live-world` и текущего образа. Не создаёт новых миров при отсутствии сохранения.
2. Собирает immutable Docker image кандидата **без монтирования живого тома**, сохраняет старый образ.
3. Останавливает только `dementor-live/game`, чтобы штатное сохранение было завершено.
4. Создаёт полный архив тома, включая `world.json`, музыку, QA-файлы; отдельную точную копию `world.json`.
5. На этой копии выполняет `tools/upgrade-audit.mjs` новым кодом: старые CharacterId, wallet/bags, plots/home/chest, ledger, ресурсы и стадии не должны уменьшиться/исчезнуть; исходный файл не пишется.
6. Только после аудита переключает тег `dementor-live:local` и запускает новый **один** контейнер с тем же persistent volume.
7. Проверяет `/api/health` и точную версию `0.5.0-rc.1`; при ошибке возвращает старый образ **и архив игрового мира**. Точное место backup пишется в `/srv/dementor-live/backups/safe-.../`.
8. Не трогает Nginx, другие сайты/контейнеры или музыку сторонних проектов. Прежний исходный каталог app остаётся конфигурационным местом; код релиза находится внутри tagged Docker image из отдельного checkout.

**Важно:** переключение приводит к короткому разрыву SSE. На время релиза организовать окно без игроков, иначе новые действия, сделанные после backup, могут быть потеряны в случае отката. После успешного запуска тестировщики должны зайти заново.

## Rollback
Автоматический при ошибке запуска — остановить candidate, восстановить полный архив тома, переназначить прежний образ, запустить только game Compose service. Сохраняйте полный архив и старый image до подтверждённой пользовательской приёмки. Для ручного отката использовать ту же сохранённую пару «старый image + backup», не один образ без world snapshot.
