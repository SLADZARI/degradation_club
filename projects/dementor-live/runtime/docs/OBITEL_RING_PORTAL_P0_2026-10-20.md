# DL-OBITEL-RING-PORTAL-P0 — кольцевой путь и городская чёрная арка
Дата: 2026-10-20. Статус: **первый играбельный срез ZEN в draft PR #293**, НЕ production.

## Зафиксированный канон
- Обитель Габеля — самостоятельный мир с **шестью областями** (ZEN, Ever Green, Prisma, Tech Priest, Virgilia, Phoenix) вокруг **Горы Гуру**. В каждой области планируются свои NPC, семь исходных точек и городское развитие. Toxic — сквозная линия, не обязательная седьмая географическая область.
- Путь проходит по кольцу вокруг горы; на дальнюю сторону нельзя попасть прямым срезом через центральный массив.
- **Вход** из основного мира — пешком до **городского портала-арки**. После постройки она выглядит как каменная/бумажно-каменная арка с **непрозрачным чёрным внутренним проходом**, а не как плоская кнопка/иконка. Физическое действие `E` или мобильная кнопка действий.
- **Обратная дверь** на дальнем конце кольца — **только выход из Обители**. Она не имеет обратного городского входа: `worldUse` снаружи отвергается. Изнутри выход доступен без прохождения всех диалогов, чтобы игрок не застрял.
- **Гора Гуру** находится в центре. Подъём отдельно разблокируется короткой цепочкой из трёх артефактов (карта, печать, существующий ключ пещеры), см. [OBITEL_GURU_MOUNTAIN_ARTIFACT_QUESTS_P0_2026-10-20.md](OBITEL_GURU_MOUNTAIN_ARTIFACT_QUESTS_P0_2026-10-20.md). Пока реальный ключ из пещеры не соединён с CharacterId, **проход закрыт**, без подмены тестовой выдачей.

## P0: что фактически внедрено в ветку
- Сцена `obitel-zen`, прямоугольник 36×27: **первый прототип кольца для одной области**, а не готовый ландшафт всех шести. Семь существующих карт ZEN сохранены с исходными стабильными ID/вопросами, `completed:false` на недописанных диалогах.
- Полилиния из 10 точек `OBITEL_RING_PATH`: (4,17) → (6,12) → (7,7) → (14,6) → (22,7) → (29,11) → (28,18) → (20,22) → (11,19) → (3,23). Серверная проходимость ограничена полосой 2.2 клетки, клиентский путь использует ту же геометрию. Нет свободного среза через центральную гору.
- На карте ZEN видна **гора** и объект `obitel-guru-gate` в статусе **preview/закрыто**. Подъём, падения, аудиенция и все шесть городов **пока не реализованы**; нельзя заявлять пользователям обратное.
- Основная городская точка `obitel-zen-entry` теперь `type:'world-portal'`, координаты **(138,72)**, не обычная бесплатная `world-gate`.
- **Постройка арки — действие игрока у объекта:** `4 wood + 3 stone` из личного рюкзака (общий вес 10 из 12 допустимых) плюс **30 PAPER из бюджета города** (тестовый баланс, не канонический тариф). Сначала E строит, второе E открывает вход. После стройки все игроки могут входить бесплатно.
- Однократная постройка `state.obitelPortal` сохраняется у города: `builtAt,builtBy,spent,consumed`. Личный кошелёк игрока не списывается. Казна дебетуется только один раз и только при `g.cityFunds()>=30`. Сервер ведёт учёт физически воплощённых дерева и камня в `cityMaterialReport`, чтобы ресурсы не «исчезали».
- Выход `obitel-zen-exit` на (3,23) возвращает в сохранённые координаты входной арки. Снаружи такого target нет. Маршруты к музею и дальним землям остаются независимыми.
- Учёт `requestId` из базового `Game.command` исключает повторную оплату при штатном сетевом дубле в пределах кэша последних 128 действий. Повторное строительство всё равно исключено стабильным `builtAt`, даже после истечения кэша.
- В туристической карте основного мира отображается точка «Арка Обители»; сама покупная карта не телепортирует.

## Важный недоделанный governance-этап
**Текущий городской runtime ещё не связывает трату казны с отдельным одобрением мэра/совета.** P0 арку может достроить любой игрок с личными материалами, если свободный остаток казны достаточен; расход ограничен одной суммой 30 PAPER на каждый город. Для production перед запуском обязателен контракт разрешения городского строительства/бюджета (или заранее утверждённый бюджет проекта). Не выдавать эту версию за защищённую муниципальную экономику.
Аналогично в текущей runtime ветке основание городов ещё не привязано к реальной покупке 5000 монет за USD — это самостоятельный релизный блокер, **новых платежей не реализовывать** в рамках арки.
