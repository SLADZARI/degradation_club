# Dementor Live 0.3.0-rc.1 — кандидат обновления

Дата подготовки: 18 октября 2026. Этот документ относится к ветке `feature/dementor-live-economy-seeds-cities-2026-10-18` и PR #261.

## 1. Причины и ожидаемый результат

Обратная связь тестировщика с iPhone:
- интерфейс закрывал игровое поле и кнопки масштабирования;
- герой иногда кружил у объекта;
- после сдачи камня на склад он «пропадал» из доступного игроку баланса, а после перезагрузки пользователь не видел его;
- в семенную лавку нельзя было физически попасть;
- нужны общественный огород и создание городов с входом других игроков.

**Точное наблюдение в существовавшем коде:** складской запас (`warehouse.stock`) был отделён от `warehouse.municipal`, зарезервированных курьерских грузов и использованных на стройках материалов (`project.consumed`). В UI не показывалась сводная ведомость. Код сохранял JSON атомарной заменой, а Docker Compose содержал постоянный volume `dementor-live-world`; достоверной проверки именно боевого save VM в этой ветке нет.

## 2. Что включено

### Материалы и экономический учёт

В `cityMaterialReport` собираются остатки добываемой древесины/камня по категориям:
- ещё в природе (карта и источники на участках/в миссии);
- суммарные запасы игроков, частные сундуки и кучи на земле;
- свободный склад, городской запас мэрии, груз курьеров в пути;
- принятые стройплощадками материалы и уже воплощённые в зданиях;
- материалы личных палаток, сырьё внутри изготовленных инструментов и накопленный лом удалённых инструментов.

**Формула:** `inNature + inBags + inChests + onGround + onWarehouse + inMunicipal + inTransit + onConstruction + inStructures + inTools + inScrap = total`.

Новые передвижения сохраняют `materialEvents` (последние 300); это журнал диагностики, не источник истины. Источник истины — сами игровые запасы, не журнал. Полный баланс виден в городской ведомости и при посещении склада. Важное ограничение миграции: для старых частных построек, созданных до этой версии, состав использованных материалов невозможно восстановить из старого save задним числом; прошлые данные не подменяются выдуманными остатками.

### Семенная лавка

Отдельная постройка в городе у координат около (23,7). Игроки сдают материалы на площадке (22,9); затем строят здание на (23,7). Мэрия оплачивает материалы и работы как городскую стройку. Покупка семян запрещена до завершения строительства; после постройки доступны морковь и конопля. Цена и ресурсы — **параметры прототипа**, не утверждённый баланс GDD.

### Общий городской огород

Отдельная строящаяся площадка около (29,18). После завершения доступны три общие грядки. Посадка расходует семя, полив — воду; урожай созревает по времени и переходит в рюкзак сборщика. Состояние роста сохраняется в городе, доступно всем его жителям.

### Реестр городов

Объект на карте около (19,6) открывает создание города и переход в доступные города. Новые города — отдельные экземпляры `Game`, с отдельными складами, проектами, деревьями, камнями, поселениями и чатом, но сохранены в одном файле сервера. Житель сохраняет личную идентичность, кошелёк, инструменты и рюкзак при переходе; он не может перейти во время работы или с невыполненным курьерским заказом. Городов в этом прототипе максимум 12 дополнительно к первому; один созданный город на основателя. Для реального масштабирования за пределы одного Node-процесса потребуются независимые сервисы/БД — не заявлены как реализованные.

### Мобильная версия

Наследуются изменения из PR #260: компактный HUD, сворачивание заданий, доступные масштаб +/−, жест двух пальцев, стабилизация пошагового движения и торможение у цели. Параллельные изменения `qa/dementor-live-chat-2026-10-18` должны быть отдельно сверены перед release.

## 3. Схема сохранения и миграция

Старый файл `data/world.json` содержал игровой мир напрямую. Новый сериализует:
```json
{
  "schema": "dementor-cities-v1",
  "origin": {"version": 1},
  "cities": {
    "city-<uuid>": {
      "name": "Название",
      "founder": "<player-id>",
      "createdAt": 0,
      "state": {"version": 1}
    }
  }
}
```
Это **иллюстрация структуры**, а не рабочий save. Реальное состояние включает ресурсы, игроков, платежи и проектные данные. На первом изменении существующего save сервер автоматически создаёт копию `world.json.before-city-upgrade-*.json` рядом с источником. **Автоматическая копия внутри того же volume не заменяет внеузловой backup.**

## 4. QA-гейты (перед выпуском)

1. `npm run doctor`; `npm run check` — синтаксис и все Node-модели, включая `city-economy.test.mjs`.
2. `npm run test:integration` — HTTP + SSE в изолированном мире.
3. `npm run test:persistence` — два отдельных запуска Node-сервера и повторное чтение одного `world.json`, сверка камня/дерева/кошелька.
4. `npm run test:mobile` — Playwright мобильный HUD, масштаб, касания, переход.
5. `npm run test:cities-browser` — два независимых Chrome-контекста, город, вход второго игрока и reload.
6. Остальные браузерные регрессии `test:compact-panels`, `test:perimeter`, `test:quests`, `test:expansion` и расширенный `[run-full-qa]`.
7. Только при полном зелёном подтверждении — Playwright фото/осмотр iOS Safari, затем ручная проверка двух живых устройств.

Пока Actions не закончился с PASS, **релизное состояние NOT VERIFIED**, не сообщать о готовом production.

## 5. Поставка

`npm run pack` создаёт `projects/dementor-live/dementor-live-workspace.zip` (без `data`, `.env`, токенов, `node_modules`, резервных копий и `.git`). GitHub Actions публикует ZIP как artifact `dementor-live-0_3_0-candidate-update` **только при успешных модельных/интеграционных проверках**. Архив — кандидат, не автоматический деплой.

## 6. Процедура обновления VM

1. Выключать/заменять только сервис Dementor Live, не трогать другие контейнеры. Сохранить SHA текущего релиза, проверить диск/том, получить экспорт `dementor-live-world` **вне VM**; убедиться, что в архиве есть реальный `world.json`.
2. Прежде чем обновлять образ, проверить что новая версия успешно стартует на **копии** production save в изолированном тестовом контейнере/порту и не изменяет оригинал.
3. После полного CI и QA — применить выбранный проверенный commit в `/srv/dementor-live/app`, пересобрать `docker compose -f deploy/compose.yaml --env-file deploy/.env up -d --build game`. Не запускать `down -v` и `prune`.
4. Проверить `/api/health`, вход прежнего персонажа, баланс материалов, население, магазин, огород, переход во второй город, повторную перезагрузку вкладки и restart.
5. При отказе: остановить **только** этот игровой сервис, вернуть предыдущий образ **и соответствующий backup save**. Старый код не обязан понимать новую `dementor-cities-v1` схему.

## 7. Известные ограничения

- На текущем шаге нет массового production-аудита старых ресурсов, нельзя автоматически восстановить неизвестные старые потери.
- Нет межгородской логистики предприятий/материалов: перенос вещей происходит только при поездке персонажа.
- Нет карт/раскладки совершенно нового мира: города создаются из того же шаблона карты, с отдельным состоянием.
- Числовые затраты на объекты и лимит городов пробные.
- Незавершённые проверки в PR и отсутствие проверки iOS Safari делают candidate недопустимым для production до подтверждения.
