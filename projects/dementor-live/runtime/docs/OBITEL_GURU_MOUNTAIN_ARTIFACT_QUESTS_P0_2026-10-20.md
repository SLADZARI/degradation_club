# DL-OBITEL-MOUNTAIN-01 — Три артефакта и доступ к Горе Гуру

**Дата:** 2026-10-20 · **Статус:** утверждаемый дизайн / технический аудит · **НЕ ИНТЕГРИРОВАНО / НЕ DEPLOYED**

## Цель и границы
Игрок должен получить **дорогу на Гору Гуру** после короткой серии действий, не дожидаясь полного написания всех 42 карточных сценариев. Изначальные 6 территорий и открытые карточки сохраняются. Создание новых больших диалогов, валют, прокачки и второй системы персонажей не входит в P0.

### Три пропуска-артефакта
1. `obitel.path-map` — «Карта пути»: выдаётся **один раз** после сохранённого ответа у исходного Аракула (`OB-C01`) в ZEN.
2. `obitel.seeker-seal` — «Печать искателя»: после взаимодействия с **двумя другими разными** существующими точками ZEN, `OB-C02...OB-C07`. Достаточно открыть и записать посещение; оригинальные незавершённые сценарии нельзя помечать завершёнными. Решение о необходимости заполненного ответа (в отличие от посещения) — оставлено для QA; для P0 предпочтительнее два посещения.
3. `obitel.cave-key` — **существующий ключ из пещеры**. Не создавать второй ключ! В изолированной ветке `feature/dementor-live-mountain-cave-fishing-p0-2026-10-20` ключ — `newCaveExplorer.keyFound` в `cave-adventure.mjs`, выставляется только при достижении `CAVE_LAYOUT.keyAt` со светом; используется для `openSecretDoor`. Для доступа к Обители нужен **проверенный на сервере** мост состояния cave→CharacterId; клиент не может присылать `keyFound:true`. Ключ остается нерасходуемым, поскольку нужен тайной двери пещеры. Изображение ключа в игровой библиотеке проверить отдельно: наличие рисунка ещё не доказывает его связь с основным инвентарём.

### Мини-цепочка без новых NPC
1. **Аракул:** поговорить/ответить на уже существующий первый вопрос. Зачесть отдельное задание «Вступление», выдать карту. Не ставить `OB-C01.completed=true`, пока реальный диалог не завершён.
2. **Две точки ZEN:** посетить любые две разные оригинальные карты кроме Аракула, показать фрагмент уже имеющегося материала/заглушку и зафиксировать серверное посещение; выдать печать. Повтор той же карты не считается второй.
3. **Пещера:** найти существующий ключ. Использовать исходный cave gameplay только после его переноса из изолированной модели в реальный серверный runtime; тестовая выдача ключа допустима лишь под серверным `qaMode`, никогда для обычного игрока.
4. **Горные ворота:** прийти к объекту у подножия **Горы Гуру в Обители**, нажать E. Сервер проверяет `scene`, `proximity`, принадлежность всех трёх артефактов одному CharacterId. Однократно записать `mountainGate.unlockedAt` и открыть проход.

## Состояние и безопасность
- Концептуальное хранилище: `player.obitel.mountainGate={version:1,visitedCardIds:[],artifacts:{'obitel.path-map':..., 'obitel.seeker-seal':..., 'obitel.cave-key':...},unlockedAt:null}`. Даты всех шагов сохранять с UTC timestamps. Внутриигровой UI может показывать «Квестовые предметы» в существующем рюкзаке — **не создавать второй кошелёк или валюту**.
- При падении с горы/рестарте права на вход и артефакты **не исчезают**. Выход/перезаход в ZEN также не сбрасывает прогресс.
- Проверки и выдача строго на сервере, атомарно, повтор по `requestId` без дублирования, повторный доступ без потребления ключа.
- Никаких начислений денег/резонанса/ачивок за заглушки, не списывать PAPER, не трогать P0 правило покупки городов за 5000 монет за USD.
- Не блокировать игрока в сцене: выход всегда доступен; ошибочные/пустые карты можно безопасно пропустить.
- P0: **дорога** открывается с тремя артефактами. Оригинальную долгосрочную структуру 6×7 не сжимать и не объявлять завершённой. Дополнительные условия **аудиенции у Гуру** и печати всех шести Домов могут быть отдельным более поздним уровнем, не отнимающим полученный ранее доступ к дороге.

## Архитектурное ограничение: не путать две горы
- Уже существующая экспериментальная общая горная тропа `WORLD_SUMMIT_TRAIL` находится в **основной сцене `city`** на ветке `feature/dementor-live-p5-footprint-biomes-routes-2026-10-20`. Модель `mountain-trail.mjs` рассчитывает высоту и расход сил, но это ещё **не Гора Гуру** и она не защищена данным квестом.
- Обитель ZEN из PR #293 — **отдельная сцена `obitel-zen` 36×27** с семью узлами. В ней **пока нет** отдельной центральной горы, ворот, узкой тропы, падений и Гуру. Новую гору нужно встроить отдельной геометрией/сценой, переиспользуя проверенные расчёты движения с другой локализацией.
- Пещера (`cave-adventure.mjs`) пока **отдельная тестовая модель**, не встроенная в `world-expansion-adapter.mjs`; keyFound не персистится вместе с общим игроком. Следовательно, **на текущей базе настоящий игрок пока не сможет честно принести ключ в ворота Обители**. Запрещено подменять это фиктивным production-флагом.

## Очерёдность безопасной реализации
**G1.** Принять контракт `obitel.mountainGate` и 3 stable artifact IDs. Сначала реализовать модель и unit-тесты без физических объектов. Флаги выдаются только проверенными событиями.
**G2.** Подключить оригинальный cave key к CharacterId в едином persistent state; пещерный тест на ключ+тайную дверь+рестарт, не выдавая ключ вторично.
**G3.** Добавить физические ворота и отдельный маршрут к Горе Гуру в Obitel (не на общей горе), серверная близость/коллизии, простой downhill fall/respawn на checkpoint.
**G4.** UI карта/печать/ключ в существующем рюкзаке, индикация 0/3, E у ворот, безопасный пропуск незаконченных карт, стиль 2D аксонометрия.
**G5.** Раздельные Node tests, HTTP/SSE и Chrome desktop/mobile, 2 независимых игрока, полный файловый перезапуск, фиксация отсутствия лишних изменений кошелька и городов, актуальный merge-base/сохранения перед деплоем.

## Минимальные критические тесты
1. Один и тот же игрок не может получить две печати за повтор одной точки; две *разные* дают печать.
2. Ключ из иной игровой сессии/другого CharacterId не засчитывается; client-supplied `keyFound:true` отвергается.
3. 2 артефакта без ключа → `LOCKED`; три проверенных → `UNLOCKED` после E у ворот; удалённое открытие запрещено.
4. Повтор `requestId` и перезагрузка не дублируют предметы/не списывают монеты; ключ не исчезает из пещерной истории.
5. Падение/выход/перезаход не закрывают дорогу, не стирают квесты.
6. Никакая неполная карта `partial` не превращается в завершённую автоматически.
7. Обычная гора из P5 продолжает работать отдельно; collision в Обители, направление движения, mobile E проходят QA.
