- **Gameplay:** исправлено появление коллизии у готовой кузницы и городского огорода поверх игроков. На время появления нового здания занятые персонажи безопасно перемещаются на доступную позицию; кошелёк, вещи, права и строительные результаты сохраняются. Отдельные модельные тесты охватывают двоих игроков и перезапуск.
- **Браузер:** текущий рюкзак и износ/смена инструментов; покупка участка через `Земля и помещения`; мобильная кнопка действия; ожидание позиции второго игрока через SSE; диагностика кликов и маршрутов.
- **Сквозные проверки:** семь последовательных этапов, плюс три экономико-городские цепочки — письмо мэру, PAPER, пейджер, второй мост, миграция персонажей.
- Версия намеренно повышена с `0.5.0-rc.2` до `0.5.0-rc.3`, чтобы отличить следующий Docker image через `/api/health`; `npm run check:release` подтверждает присутствие исправлений и защит.
- **Не входят без отдельной реализации:** новые плитки земли, переработка всей экономики NPC, новые сюжетные ветви, Университет и контент других самостоятельных веток.

## Ограничения перед публикацией (RELEASE GATE)

1. Просмотреть [PR кандидата](https://github.com/SLADZARI/degradation_club/pulls), убедиться, что весь набор проверок на **последнем полном SHA** ветки зелёный, а конфликтов с основной релизной веткой нет: `Seven Sequential Gates 7/7`, `RC3 Chain Regression`, `Save-Preserving Release Gates` (model/upgrade, Chromium, Docker), `Land/Mayor`, `Payphone/Bridge`.
2. Удостовериться, что Paper Cut UI v2 CLEAN сохранён: исходные оригинальные SVG, PNG и атласы, `npm run check:icons`.
3. На VM установить **только** отдельный clean checkout по одобренному 40-символьному SHA, не используя `/srv/dementor-live/app` как checkout. Убедиться, что все игроки вышли и наступило окно обслуживания. Зафиксировать текущее `/api/health`, image ID, существующий том `dementor-live-world`, свободное место, прежний commit и конфигурацию Compose.
4. На сервере в каталоге `projects/dementor-live/runtime` выполнить `npm run check:release`, `bash deploy/publish-preserve-world.sh --dry-run`. Если что-то не совпадает, **STOP**.
5. **Только после одобрения и прохождения dry-run:** `bash deploy/publish-preserve-world.sh --apply <APPROVED_FULL_40_CHAR_SHA>`. Скрипт блокирует неправильный SHA, фиксирует старый image, останавливает только game service, сохраняет полный `dementor-live-world` и отдельный `world.json`, выполняет `tools/upgrade-audit.mjs` на архивной копии и только затем переключает image. После запуска проверяет `0.5.0-rc.3` в health и оригинальные иконки; при неуспехе восстанавливает прежний образ и полный том.
6. После cutover — ручная приёмка двух игроков, существующих персонажей и токенов, PAPER, склада, дома, земли, пейджера, строительства, выхода из кузницы, мобильной навигации и визуального наложения объектов. Обязательно проверить iPhone Safari; Chromium device emulation это не заменяет.
7. Сохранить итоговый точный SHA, image ID, URL CI, UTC-дату, путь к полной резервной копии и акт приёмки. Старый образ и backup **не удалять** до окончательного подтверждения.

**Запрещено:** `publish-clean-world.sh --reset-world`, `docker compose down -v`, `docker volume rm`, удалять/подменять боевой `world.json`, деплоить из непроверенной ветки, запускать upgrade без full-volume backup.
