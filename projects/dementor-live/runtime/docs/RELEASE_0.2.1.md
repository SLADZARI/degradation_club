# Dementor Live 0.2.1 · подготовка отдельного запуска на сервере

Дата: 18 октября 2026. Эта версия подготавливает изолированный запуск на VM. Она сама по себе не означает, что игра уже развёрнута или доступна из интернета.

## Изменения

- Добавлен собственный Docker Compose для сервиса `dementor-live`, порта `14173` и сохраняемого тома `dementor-live-world`.
- Публичный корневой адрес задаётся через `DEMENTOR_PUBLIC_URL`; его Host и Origin принимаются сервером вместе с уже работающими localhost/LAN-адресами.
- Health endpoint получает версию из `package.json`.
- Инструкция ограничивает команды и файлы директорией `/srv/dementor-live`; старые приложения, `/data/*`, `/srv/dementor/stage-a`, Nginx и другие Compose-проекты не затрагиваются.
- `.dockerignore` исключает реальное сохранение, резервные копии, секреты и локальные зависимости из образа.

## Проверки

- `npm run doctor` — PASS.
- `npm run check` — PASS, 48/48 модельных тестов.
- `git diff --check` — PASS.
- Изолированный HTTP smoke-check: точные Host и публичный Origin приняты (200); посторонний Origin отклонён (403).
- Docker build, SSH-инвентаризация, перенос мира и запуск на сервере — NOT RUN. Локальный Docker CLI отсутствует; строгая SSH-проверка остановилась на неподтверждённом host key.

## Первый перенос

До запуска на VM нужно подтвердить SSH-отпечаток сервера и проверить текущие занятые порты и Docker. Скопировать согласованный `data/world.json` и `data/music/` в отдельный том; сохранить датированный резервный снимок. После этого серверное сохранение становится авторитетным. Имена игроков/токены привязаны к браузерному хранилищу прежнего адреса и при переходе на новый origin могут потребовать повторного входа.
