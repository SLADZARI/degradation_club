## Этап 0: скачать и просмотреть скрипт на своём Mac

```bash
curl -fL \
  'https://raw.githubusercontent.com/SLADZARI/degradation_club/docs/dementor-live-city-ownership-and-wilderness-01/projects/dementor-live/runtime/ops/isolated-preview.sh' \
  -o isolated-preview.sh
less isolated-preview.sh
```

**НЕ** выполнять `curl | bash`. Скрипт должен быть прочитан и закреплён в исходниках. Дополнительно можно `bash -n isolated-preview.sh` на Mac. SSH-ключ в чат/репозиторий/ZIP не отправлять.

## Этап 1: read-only preflight, на сервере ещё ничего не меняем

```bash
ssh -i ~/.ssh/dementor_server root@138.199.144.94 \
  'bash -s -- preflight' < isolated-preview.sh
```

Ожидается `Preflight PASS`. Скрипт проверяет Docker, Git, свободное место, занятость 14173, существование имени нового контейнера и наличие `/srv/dementor`. При конфликте — **ABORT без создания файлов**. Если скрипт пишет BLOCKED, передать вывод для коррекции; не менять старые службы ради установки.

## Этап 2: установка только после PASS

```bash
ssh -i ~/.ssh/dementor_server root@138.199.144.94 \
  'bash -s -- install' < isolated-preview.sh
```

Изолированно получает git SHA, проверяет его, запускает Node model tests (отдельный `docker run --rm` без сети), создаёт собственный каталог сохранений, затем **только один новый контейнер** `dementor-live-preview-020`. Проверяет `/api/health` на localhost:14173. Не применяет системные пакеты, не перезапускает Nginx, не останавливает и не пересоздаёт ни один существующий контейнер.

**Если GitHub недоступен, код/коммит не совпадает, тесты падают или порт занят:** установка останавливается. Созданный `/srv/dementor/live-preview` после частичной установки сохраняется для диагностики; не удалять и не повторять команду с игнорированием ограничений.

## Этап 3: read-only контроль + просмотр двух клиентов

```bash
ssh -i ~/.ssh/dementor_server root@138.199.144.94 \
  'bash -s -- status' < isolated-preview.sh
```

Должен быть только один новый контейнер, host bind только `127.0.0.1:14173`, ответ `{"ok":true,"version":"0.2.0","testMode":false}`. С Mac запустить SSH-туннель из предыдущего раздела, открыть два независимых браузерных контекста, войти под разными именами, проверить общие позиции/чат, UI, сохранение после reload. До боевого доступа проверить, что `docker ps` по существующим именам и `ss` на 80/443/18080 не изменились (сравнение со снимком до установки).

## Откат без потери сохранений

Если что-то не так, **остановить только свой новый контейнер**:

```bash
ssh -i ~/.ssh/dementor_server root@138.199.144.94 \
  'docker stop dementor-live-preview-020'
```

**Никогда не выполнять здесь** `docker system prune`, `docker compose down` без целевого проекта, `rm -rf /data`, `systemctl restart nginx`, глобальный `apt upgrade`, удаление volume/database, изменения DNS/сертификатов или публикацию порта 4173/14173 наружу. Отдельная игровая директория с сохранениями остаётся на диске даже после остановки нового контейнера.

## Почему пока не публично

Существующий `server.mjs` разрешает Host/Origin для `localhost` и сетевых IP с ожидаемым портом, но не поддерживает готовую привязку публичного домена, сильные учётные записи, защиту от массовых регистраций/злоупотреблений, безопасный общедоступный reverse proxy и требуемые меры для интернет-публикации. Даже при успешных локальных тестах **не** открывать сервис через Nginx/GoDaddy до отдельной проверки безопасности, авторизации, TLS и резервного копирования.
